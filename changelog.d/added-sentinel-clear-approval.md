- **Optional: a trusted merger who removes the Sentinel label also approves that head (`sentinel.clear_counts_as_approval`, off by default).** A maintainer who read a flagged diff and removed the `sentinel-alert` label had made the trust decision, but a reviewer verdict of `requires_human` on the same head (often asking for that very trust review) still parked the pull request at `stage/085-needs-decision` until the same person approved it a second time. With the setting on, the Sentinel sweep reads who removed the label from GitHub's own label event and, when that person is a trusted merger (a merger or owner in `dashboard.authorized_users`: the test a GitHub Approve review must pass, never a bot, the hive App or the pull request's own author) and the label came off after that head was pushed, records their approval of the head in the decision ledger a dashboard Approve writes to. That answers `requires_human` on the head whether the verdict came before or after, and a new head needs a new decision. Because it is a full approval, it covers every question the reviewer raised, not only Sentinel's, and like any approval it admits an outside contributor's head for the hive to merge once the other gates pass; `hold` labels, human-merge paths, the workflow-file fence and required checks are unchanged. Hive notes who removed the label on its own Sentinel comment, writes a `sentinel-clear-approval` audit entry, marks the head `[sentinel-cleared: @login@sha]` in the queue reviewer's list so the reviewer judges it normally (`${SENTINEL_CLEARED}` in `reviewer-queue.md`), and says in the 085 comment that removing the label also approves the head. Set it in hive.yaml, in Settings → Security → Suspicious Activity, or through the admin MCP `sentinel.settings` operation, whose preview discloses turning it on as a widening. With the setting off, nothing changes.
