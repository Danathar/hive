- ACMM's `acmm:prereq-code-style` criterion now recognizes explicit formatter and linter configuration beyond the JS/Python/Go files it already accepted, including shell/editor style (`.shellcheckrc`, `.editorconfig`), C/C++ (`.clang-format`), Java Checkstyle (`checkstyle.xml`, `config/checkstyle/checkstyle.xml`), Ruby RuboCop, Rust rustfmt/clippy, SwiftLint, Stylelint, and additional golangci-lint config extensions ([#5903](https://github.com/hivecommons/hive/issues/5903)). Because this is an L0 prerequisite, repositories written in those languages were pinned below Level 0 and could see the same gap issue re-filed after adding a valid style config. Broad manifests such as `package.json`, `go.mod`, `Cargo.toml`, or `Makefile` are still not accepted, so the criterion does not become a trivial match for repos without code-style configuration.
