- The `dibs.hivecommons.dev` cutover runbook gained a zero-cost preflight and three sharper verification steps ([#5925](https://github.com/hivecommons/hive/issues/5925)). The sequence is scheduled around a Let's Encrypt quota window, which makes the expensive failure not "a step fails" but "a step fails *after* the certificate has been re-issued" — that spends the window the whole plan waits for and puts the next attempt a week out. `src/deploy/dibs-domain-cutover/preflight.sh` checks the plan's assumptions read-only and in advance: that the ingress-nginx controller's `--default-ssl-certificate` really is `hive-hub/hive-wildcard-tls` (the staged Ingress gives the new host no `tls:` block and cannot — an Ingress may only name a Secret in its own namespace — so if that flag is absent the host is served ingress-nginx's **self-signed** certificate, answering `200` while failing validation); that the Certificate exists where the patch targets it and does not already carry the SAN; that the live `dibs/dibs` Ingress has not drifted from the staged full-object copy, whose apply would silently drop any annotation it omits; that neither host is claimed by two Ingresses, which ingress-nginx resolves in favour of the older one with only a log line, leaving a redirect inert; that the DNS record points where step 1 says; and that the Let's Encrypt registered-domain window still has headroom, estimated by a read-only crt.sh count rather than any ACME probe. A check it could not run reports as a warning, never as a pass. The runbook now also verifies the certificate chain and SANs rather than just a `200`, states that the legacy host must be removed from the application Ingress *before* the redirect is applied and why, tests the redirect on a deep path with a query so one that drops `$request_uri` cannot pass a `/`-only check, and names the dual-host window as a verification window rather than a resting state — the legacy host is knowingly signed-out for as long as it stays open. Contract tests: `bin/test_dibs_cutover_preflight.sh`.
