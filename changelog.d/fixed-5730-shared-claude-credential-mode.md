- A Claude fleet no longer drops to login prompts hours after boot when a token refresh rewrites the shared credential owner-only ([#5730](https://github.com/kubestellar/hive/issues/5730)). Agents share one operator login through `/data/home/.claude`, but Claude Code refreshes that OAuth credential roughly every 8 hours and writes the replacement `0600` as whichever agent refreshed it — locking out every other agent uid, which reaches it through the `node` group. Measured on a live hive: five of six agents went `auth-required` within 30 minutes of a refresh, the survivor being the agent that owned the file, while the credential itself held a live access token and a valid refresh grant. Three repair paths were supposed to prevent this and all three missed. The entrypoint's `.claude` guards died silently: `entrypoint.sh` runs under `set -e`, backgrounded guard subshells inherit it, and `chmod -R` over a tree Claude Code is actively writing returns non-zero the moment an entry vanishes mid-walk — so the two guards that walked that 161 MB tree ended permanently while the three that did not survived. Guard bodies can no longer fail, a watcher that exits is logged and restarted with backoff instead of ending its guard, and the instant path now reopens the credential rather than re-walking the whole tree on every write. The in-process permissions watcher gained a shared-credential carve-out so it repairs the file instead of skipping it as another uid's, and reports at ERROR — with the mode, the owner and the exact `chmod` — when it cannot. And the credential watchdog no longer reports an unreadable credential as `login expired (no usable refresh grant)` prescribing a device-flow login that cannot help; it names the permission failure and the one-line fix.
