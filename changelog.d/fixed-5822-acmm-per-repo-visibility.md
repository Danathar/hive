- The dashboard's ACMM Evaluation panel now shows which repo is lagging, instead of one fleet-wide level that hid it ([#5822](https://github.com/kubestellar/hive/issues/5822)). The headline number is a union across watched repos — a criterion counts as passed if *any* repo has it — so a repo meeting none of the 43 criteria did not move it at all and was effectively invisible; and the per-repo drill-down was half-wired, so clicking a repo chip moved the level bars while the four headline tiles above them kept reporting hive-wide numbers, two halves of one card disagreeing with nothing to say which had followed the click. The tiles now resolve the selected repo *before* they are written, Overall ACMM is recomputed as min(selected repo's codebase level, operational level) rather than silently keeping the fleet-wide reading, and Operational Autonomy — which measures the hive and not a repository — stays hive-wide and is now labelled as such, so the card's mixed scope is stated rather than left looking like a tile that failed to update. A new per-repo table ranks every watched repo weakest-first by unmet-criteria count, showing its level, `passed/total`, and the level it is blocked at, with rows that select their repo; the chips carry the ratio alongside the level, so "lacking, and by how much" no longer costs one click per repo. The panel itself now states that the aggregate is a union — previously that was mentioned only inside the Codebase Readiness dialog — and the repo selector no longer flashes visible before the first fetch, having carried both `display:none` and `display:flex` in one style attribute. No new data collection or GitHub API calls: the evaluation already returned per-repo results.
