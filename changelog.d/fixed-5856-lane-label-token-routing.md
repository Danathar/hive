- Lane routing no longer matches keywords inside a label's name, so the `ai-fix-requested` label stops sending every ACMM gap issue to an agent that cannot fix it ([#5856](https://github.com/hivecommons/hive/issues/5856)). Issues route to one agent by matching lane keywords against the title *and* the labels, and the match was `strings.Contains` over the space-joined label list — so scanner's L4 keyword `fix` matched inside `ai-fix-requested`, the label the dashboard's ACMM evaluator stamps on every maturity-gap issue it files. Every ACMM issue therefore routed to scanner, which is `ISSUES_ONLY` at L4 and cannot open a pull request, while `quality`, `ci-maintainer` and `sec-check` never saw it: `filterByLane` admits an issue to an agent only when the lane matches its name or is empty. A live 4-repo L4 hive had 11 of 11 ACMM issues parked there with nothing logging an error. The label whose entire purpose is to mark an issue AI-fixable was the reason nothing fixed it — toggling only that label moved "[ACMM L4] Add AI security policy" from `sec-check`, which would have fixed it, to `scanner`. Keywords and lane names now match a label only as the whole label or as a whole `/`-delimited segment of it, so `kind/regression` still routes on `regression` (that separator is a GitHub namespace convention the classifier already relies on) while `ai-fix-requested` no longer routes on `fix` — and a multi-word keyword can no longer straddle two unrelated labels, which is how `breaking change` used to match an issue labelled `breaking` plus `change`. Titles keep substring matching, which is right for prose. Separately, the lane table itself was built by ranging over a Go map, so an issue matching two lanes went to whichever came out of the map first and the winner could change between two runs of the same binary on the same config; it is now sorted by name before it reaches the classifier. That collision is real on an L4 hive, where "Add AI fix workflow" matches both `ci-maintainer` and `scanner` — agents with different modes, so the coin flip decided whether the issue was fixable at all. Note the fix makes the ACMM labels routing-neutral rather than re-homing every ACMM issue: titles matching no lane keyword still fall back to `DefaultLane = "scanner"`, which keeps them invisible to other agents, and changing that fallback is a routing-policy decision left open.
