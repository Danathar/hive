- The fix-loop circuit breaker no longer re-posts its "Fix loop escalated — human attention needed" comment on a PR that has already been escalated. The ledger entry for a red PR — including its *escalated* marker — was deleted on any pass that did not see CI as `failure`, and `EnrichCIStatus` reports `pending` for a check-run fetch that *errored* as well as for checks that are still running. One transient GitHub API error therefore re-armed the breaker, and the next red pass burned a fresh re-engagement budget and escalated again: on one hive, a single PR collected fifteen identical escalation comments in 32 hours and another twenty-five. Three changes close this. A `pending` observation now leaves the ledger untouched (it is no information, not a green), and an entry that merely drops out of one enumeration pass is kept for 24h before it is pruned. The `needs-human` label is now the authoritative record of escalation in both directions: a PR that already wears it is treated as escalated even by a freshly-wiped ledger, so the comment can never be posted twice, and a PR whose confirmed label a human later *removes* is genuinely returned to the automated lane (fresh distinct-SHA count and re-engagement budget) — previously the ledger's own flag kept it hands-off forever, so the comment's "remove the label to return the PR to the automated fix lane" instruction did nothing. A label call that fails at escalation time is retried on later passes without re-commenting, with a 5-minute grace so a stale listing right after the label write is not read as a removal.
- Escalation triggered by an exhausted re-engagement budget on a head that never moved now says so ("stayed red on the same commit through N automated fix re-dispatches with no new commit pushed") instead of the misleading "1 distinct fix attempts".
- Dependency-bot PRs (`renovate[bot]`, `dependabot[bot]`, `mergeraptor[bot]`) are no longer treated as hive-agent PRs by the fix-loop machinery. The agent-author test was "configured `ai_author`, or any login ending in `[bot]`", which swept every red Renovate/Dependabot bump into the staleness clock, the reaper, and human escalation — paging a human about crate bumps that no agent had ever touched. The list mirrors the hub's default `hub.contribute_deny_authors`, and the shared `isHiveAgentAuthor` check also recognises the App identity from `EffectiveAIAuthor()`.
