- Contributor task assignments now name the branch the work belongs on, so a session's PRs no longer inherit whatever branch the previous task left the persistent checkout on ([#5729](https://github.com/kubestellar/hive/issues/5729)). The prompt mentioned a branch exactly once — "push your branch to your fork" — and never said which branch to start from or target, while nothing resets the checkout between tasks; one `[v5]`-titled issue was therefore enough to redirect every later PR of a session. On 2026-09-02 five consecutive PRs landed on `v5`, only the first correctly, and three of the rest were fixes for defects live on the deployed `v4` that had to be backported by hand. Assignments now tell the agent to start its work branch from the base, open the PR with `gh pr create --base <branch>`, and confirm the base before reporting done. The base is the branch the hive is built from — the same branch the contribute onboarding page already tells contributors to clone — unless the issue's title carries a release-line tag such as `[v5]`, which wins.
