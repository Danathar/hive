- The scheduled v4 test run no longer fails with a data race in `pkg/dashboard` ([#5985](https://github.com/hivecommons/hive/issues/5985)). `TestPollCopilotToken_SlowDownBumpsInterval` ran the poller in a goroutine it did not own: on a `select` timeout it called `t.Fatalf`, which runs the test's cleanups, and those restore the package-level `copilotAccessTokenURL` / `copilotUserTokenPath` vars that the still-running poller reads. So a timing flake did not fail as a timing flake — it failed as a **DATA RACE** that took the whole `-race` package down, and the abandoned goroutine went on mutating package state under later tests. The margin was thin because the test had to live through the production 5-second slow_down bump in real time with an 8-second budget, which a loaded `-race` shard ate. All seven poll tests now start the poller through a helper that owns it with a cancelable context and joins it in a cleanup registered to run *before* the vars are restored, so the timeout path is no longer a race; the slow_down bump joins the URL and path vars as an injectable `var` so the test proves the same behaviour with a 1-second bump. The test went from 15.6s (failing) to 1.0s, and the package is clean under `-race`.
