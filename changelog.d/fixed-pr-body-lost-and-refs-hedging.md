- Agent-opened PRs can no longer go out with an empty body. `hive-open-pr` used to silently drop `--body-file` (a flag `gh pr create` accepts and agents routinely use), so the request carried an empty body and the opened PR's only content was the attribution footer — observed repeatedly on quality/sec-check PRs. The script now honors `--body-file`/`-F` (and the gh short flags `-R/-H/-B/-t/-b`), warns on any other flag it drops, and refuses an empty body loudly; the PR-request watcher independently rejects an empty body at the server-side choke point, so no client can open a body-less PR.
- Agent PRs that resolve an issue now close it on merge. The policy templates and kick instructions hedged closing keywords ("`Fixes #N` ONLY if this fully resolves it — use `Refs #N` instead for an epic/multi-phase tracker"), which agents read cautiously enough that about half of resolving PRs shipped a non-closing `Refs #N` and left their issue open after the fix landed. The guidance now makes `Closes #N` the stated normal case and confines `Refs #N` to a deliberately-partial fix that must say, on the same line, what is left open and why. A new `hive-open-pr --issues <N>` declares the originating issue, and the watcher rejects a request whose body no longer references each declared issue — so a truncated body cannot open a PR that orphans its issue.
