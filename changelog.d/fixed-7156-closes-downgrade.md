- The PR-request watcher no longer withholds a PR's closing keyword because the issue carries the `- [ ]` completion criterion the policy templates mandate ([#7156](https://github.com/hivecommons/hive/issues/7156)). Every one of the 18 templates tells a filing agent that an unsplittable finding must state its definition of done as a task list, and the watcher then rewrote that PR's `Closes #N` to `Refs #N` for having one — so an agent could do the whole job, merge green, and leave the issue open forever, drawing triage attention and being re-offered as unfinished work 72h later. The compensating task-list sweep could not recover it, because nothing in the tree ever ticks a box. The downgrade now fires only for a list that genuinely delegates work elsewhere — an unchecked item whose subject is another issue (`- [ ] #123`, `- [ ] owner/repo#12`) — which keeps the gate's purpose intact for multi-phase trackers, including the one- and two-item lists the `epic`/`tracker` labels, the title prefixes and `IsTrackerIssue` all miss. Boxes inside fenced code blocks no longer count either, so an issue that merely quotes the policy's own `- [ ]` example is not penalised for the quote; the downgrade gate and the sweep now read a body the same way.
- A downgraded reference explains itself in the PR body it lands in — `Refs #318 — closing keyword withheld by the hive watcher: <reason>. Merging this PR will not close the issue.` ([#7156](https://github.com/hivecommons/hive/issues/7156)). Previously the only record was a WARN line in a container log with a day or two of retention, so a merged `Refs #N` was indistinguishable from an agent that deliberately chose not to close — which also means some share of the 22% `Refs`-only rate measured in #6547 may have been this rewrite rather than agent caution. Titles are still rewritten without the note.
