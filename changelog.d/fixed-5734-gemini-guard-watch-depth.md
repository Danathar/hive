- The permission guard protecting antigravity's (`agy`) shared OAuth token now watches the directory the token is actually in ([#5734](https://github.com/kubestellar/hive/issues/5734)). `agy` keeps its credential at `.gemini/antigravity-cli/antigravity-oauth-token` — one level below the guard's watch — and `inotifywait` without `-r` reports events only for entries directly inside the watched directory, so the guard could never fire for the file it exists to protect. It was not merely untested but structurally incapable of firing, while reading as protection: on a live hive, sixteen minutes and one token rewrite after boot, the `.claude` guard's watcher pid had advanced while `.gemini`'s was still the boot pid. That left a single mechanism guarding a shared credential, the same 5-minute sweep observed dying silently in #5730. The `.gemini` guard now watches recursively, its directory is pre-created at boot so the watch covers it from the start, and `/data/home/.gemini` joins `WatchedHomeDirs` so the in-process watcher is a real fallback rather than absent. The entrypoint ownership test now asserts on credential PATHS rather than directories — as written it could not fail for a credential that moved into a subdirectory, which is exactly what had happened.
