- `project.standing_approvals` lets a hive owner approve a narrow kind of change once, in advance (for example "advisory CI checks" or "test-only rows"). Each entry is shown to issue-filing lanes as `${STANDING_APPROVALS}`; an agent that names an entry with `hive-open-issue --needs-decision --standing-approval <id>` gets the issue filed actionable instead of parked, but only when the entry covers that repo and lane and the issue's `Risk:` line is a governance question outside the excluded topics (security, credentials, licensing, branch protection, merge policy, spend, data loss). Every use is recorded in the issue body and the audit log.
- An accepted gate proposal now settles its class in every repository the hive serves, not only the ones it listed: lanes file the accepted gate as actionable work in a new repository, citing the ruling, instead of asking the owner to approve the same proposal again.
