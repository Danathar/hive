- The dashboard's **Sign in with GitHub** overlay completes again ([#6216](https://github.com/hivecommons/hive/issues/6216)). [#5748](https://github.com/hivecommons/hive/issues/5748) made `flow_id` mandatory on `/api/gh-user-auth/poll` — the binding that stops an anonymous poller racing the operator for a freshly approved session — and taught the standalone login page and `hivectl login` to send it, but missed the in-page overlay in `static/index.html`. That overlay kept polling with an empty body, so every poll was refused with 400 and the login could never complete: GitHub reported the device activated while the dashboard sat on "Waiting for authorization..." indefinitely, with no error. It affected only hives where the dashboard page loads before you sign in (an open hive, or one already carrying `HIVE_DASHBOARD_TOKEN`) — everyone else got the standalone login page, which was never broken, which is why this survived from the 2026-09-02 merge through v4.18.1. The overlay now keeps the `flow_id` from `/start` and presents it on every poll. It also stops on a response it does not recognise and shows the error, instead of silently looping: the 400 body carried `{"ok":false,"error":...}` with no `status` field, so it matched none of the overlay's branches and the timer just fired again — an eternal spinner rather than a message. A regression guard now asserts the page's poll actually carries the id, which is the check that would have caught the original miss; the server-side tests could not, because the browser was the thing being correctly rejected.
